---
name: Orval-generated query hook queryKey requirement
description: Why generated TanStack Query hooks fail typecheck when passing `enabled` without `queryKey`, and how to fix it.
---

When a project uses Orval to codegen React Query hooks from an OpenAPI spec, the generated hook signatures type the `query` option as `UseQueryOptions<TQueryFnData, TError, TData>` (only 3 generics, no explicit `TQueryKey`). With TanStack Query v5 installed, passing just `{ enabled: someBoolean }` as the `query` option fails typecheck with "Property 'queryKey' is missing".

**Why:** The 3-generic instantiation of `UseQueryOptions` used by this Orval codegen setup does not default `queryKey` the way callers expect, so partial objects like `{ enabled }` don't structurally satisfy it.

**How to apply:** Whenever adding `enabled: ...` (or any other option) to a generated hook's `query` object, also import and pass the matching `getXxxQueryKey(...)` helper (also generated by Orval) as `queryKey`, e.g.:
```ts
useGetDashboard(profileId, { query: { enabled: !!profileId, queryKey: getGetDashboardQueryKey(profileId) } })
```
This applies across all generated query hooks in the project (list, get-by-id, get-with-params, etc.) — check for this pattern first if a fresh Orval codegen run introduces this typecheck error again.
